# Ecloud Lite 路线图

本文记录当前工程估算，不代表官方兼容性承诺。`[x]` 表示已经达到该项当前阶段的目标，`[ ]` 表示尚未完成；“已测试”只代表在当前测试环境和账号策略下有证据，不代表所有版本兼容。

## Step 1：接入官方 runtime

目标：保留官方 CMSS renderer 负责现阶段的画面和设备能力，Lite 负责登录、资源管理、连接编排、会话切换、日志和生命周期管理。官方客户端没有的诊断、会话档案和便携化能力也可以继续加入。

当前总体预期进度：约 78%。这是按大类的工程估算，不是代码行数比例。

| 大类 | 当前预期进度 | 已实现 | 已测试 | 当前判断 |
| --- | ---: | :---: | :---: | --- |

| 多账号与本地会话 | 100% | [x] | [x] | 会话保存、切换、过期提示和重新登录更新已验证 |

### Step 1 已实现但仍需现场回归的范围

- [x] 三种登录模式与验证挑战的协议分支。
- [x] 多账号保存会话、快速切换和 DPAPI 本地保护。
- [x] 云电脑列表、后端识别、连接参数和 Path B 探测。
- [x] 官方 runtime 的启动编排、Lite 侧断开和精确进程清理。
- [x] 详细脱敏日志、离线自测、程序目录数据和 profile 镜像。
- [ ] 电源操作、在线时长和不同桌面状态的完整回归。
- [ ] 官方 renderer 的键鼠、音频、剪贴板、退出提示、重连和多显示器回归。
- [ ] 非 `CMSSZTE` 后端的实际连接能力。

## Step 2：抛弃官方 runtime

目标：不再依赖官方 renderer、官方动态库、官方 Qt 插件或官方运行时目录，使用可审阅、可构建、可分发的开源组件实现完整功能。

此阶段尚未开始功能实现，以下只按大类记录方向，不拆分具体项目：

| 大类 | 当前预期进度 | 状态 |
| --- | ---: | --- |
| 开源传输与网关适配 | 5% | 研究资料和协议探测原型 |
| 开源桌面显示与渲染 | 0% | 未开始 |
| 输入、音频和剪贴板能力 | 0% | 未开始 |
| 会话生命周期、心跳和重连 | 5% | 有协议分析基础，未形成独立实现 |
| 多后端兼容 | 0% | 未开始 |
| 跨版本测试和可分发构建 | 0% | 未开始 |

Step 2 的完成标准是：在不携带官方 runtime 的情况下，完成授权环境中的登录后连接、画面、输入、音频、退出和重连回归，并能由公开源码构建可审阅的客户端。
