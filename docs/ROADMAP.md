# Ecloud Lite 路线图

本文记录当前工程估算，不代表官方兼容性承诺。`[x]` 表示已经达到该项当前阶段的目标，`[ ]` 表示尚未完成；“已测试”只代表在当前测试环境和账号策略下有证据，不代表所有版本兼容。

## Step 1：接入官方 runtime

目标：保留官方 CMSS renderer 负责现阶段的画面和设备能力，Lite 负责登录、资源管理、连接编排、会话切换、日志和生命周期管理。官方客户端没有的诊断、会话档案和便携化能力也可以继续加入。

当前总体预期进度：约 89%。这是按大类的工程估算，不是代码行数比例。

| --- | ---: | :---: | :---: | --- |

### Step 1 已实现但仍需现场回归的范围

- [x] 三种登录模式与验证挑战的协议分支。
- [x] 多账号保存会话、快速切换和 DPAPI 本地保护。
- [x] 云电脑列表、后端识别、连接参数和 Path B 探测。
- [x] 不依赖官方 runtime 的单设备 Path B 保活、实时统计、最终连接摘要和生命周期停止。
- [x] 官方 runtime 的启动编排、Lite 侧断开和精确进程清理。
- [x] 缺少 runtime 时提示、官方下载引导、7-Zip 检测/下载和官方安装包本地最小化提取。
- [x] 官方 runtime 下的键鼠、组合键、中文输入法、文本/文件剪贴板、扬声器、麦克风和网络重连。
- [x] Lite 主程序“断开云电脑”作为当前可靠退出入口。
- [x] 解析 renderer 的 `1010/msg_type=10` toolbar 控制帧，将最小化转发给原生窗口，并让两个退出入口复用 Lite 断开流程。
- [x] 断开确认框以 renderer 原生窗口作为 owner，确保显示在云电脑窗口之上；句柄不可用时回退到 Lite 主窗口。
- [x] 详细脱敏日志、离线自测、程序目录数据和 profile 镜像。
- [ ] 开机、关机、重启和不同桌面状态的完整回归；当前仅在线时长已测试。
- [ ] 单设备保活的数小时/数天现场回归、断网恢复、Token 过期和服务端策略验证；多设备保活暂不实现。
- [ ] 退出菜单中的重启、关机和锁屏动作；当前版本只接入断开退出，不代替云电脑电源接口。
- [ ] 分辨率、全屏、缩放和多显示器回归。
- [ ] 重复启停、renderer 崩溃、Lite 退出和残留进程清理回归。
- [ ] 扩大 Windows 版本、目录权限、官方客户端版本和账号策略兼容矩阵。
- [ ] 非 `CMSSZTE` 后端的实际连接能力。

## Step 2：抛弃官方 runtime

目标：不再依赖官方 renderer、官方动态库、官方 Qt 插件或官方运行时目录，使用可审阅、可构建、可分发的开源组件实现完整功能。

此阶段尚未开始功能实现，以下只按大类记录方向，不拆分具体项目：

| 大类 | 当前预期进度 | 状态 |
| --- | ---: | --- |
| 开源传输与网关适配 | 5% | 研究资料和协议探测原型 |
| 开源桌面显示与渲染 | 0% | 未开始 |
| 输入、音频和剪贴板能力 | 0% | 未开始 |
| 会话生命周期、心跳和重连 | 15% | 已有独立 Path B 单设备心跳保活；显示会话重连仍依赖官方 runtime |
| 多后端兼容 | 0% | 未开始 |
| 跨版本测试和可分发构建 | 0% | 未开始 |

Step 2 的完成标准是：在不携带官方 runtime 的情况下，完成授权环境中的登录后连接、画面、输入、音频、退出和重连回归，并能由公开源码构建可审阅的客户端。
